# Managed training provenance and recovery

The application persists derived Brush provenance in `training/training-fingerprint.json` (schema version 1, [schema](../../schemas/training-state.schema.json)). The digest binds the actual normalized dataset file names and contents, preparation provenance, actual Brush executable/version, any Windows live companion executable, effective training parameters, CLI/backend and relevant profile fields. The managed `init.ply` copy and its temporary file are excluded. Run UUID, OS patch label and fresh probe observations do not invalidate otherwise identical training inputs.

Before launching Brush, the state has `completed: null`. Only a successful process exit followed by full final Gaussian PLY validation can produce completion metadata. Completion binds the expected iteration count, checkpoint content SHA-256 and result JSON SHA-256. A target-named checkpoint left by a failed or cancelled process is therefore insufficient to satisfy the cache. Training also rechecks the input/executable fingerprint after process exit. The result records the effective iteration count, SH degree and profile resolution; legacy result JSON remains readable through optional new fields.

A matching incomplete state may warm-start from the latest complete valid checkpoint below the target, only if the runtime supports geometry warm start. Corrupt checkpoints remain available but are skipped. Optimizer state is reset. The macOS adapter rejects a checkpoint whose SH degree or Gaussian count cannot be retained under the new profile. A changed fingerprint, legacy/unknown provenance, or unsupported warm start starts fresh after preservation.

Previous `training/checkpoints`, `training/result.json`, fingerprint metadata and managed initial-geometry files move to `runtime/previous-training/<unique-id>/`. The previous dataset is independently preserved by the preparation stage. No source media is deleted. [The version 1 archive journal](../../schemas/training-archive-journal.schema.json), at `training/archive-journal.json`, records the entire move set before the first rename. After interruption, each move is accepted only when exactly one of source and destination exists. An already moved destination advances recovery; ambiguous source/destination pairs stop with an actionable error and preserve both. The completed journal is retained as `archive.json` inside the archive.

Metadata publication uses a synced temporary file and replacement rename; Unix parent directories are synced after publication and archive moves. Filesystems and operating systems still determine crash durability. If metadata is malformed, it cannot authorize cache or resume and is preserved with the archive. Future state/journal schema versions fail without a downgrade. There is no destructive migration: old untracked results are archived when a new run needs provenance.

Automated Rust tests cover content and parameter invalidation, unchanged run/probe identity, successful-result hash binding, invalid PLY rejection, interrupted multi-file archives, conflict preservation, malformed legacy data, unsupported future versions, and managed-dataset symlink rejection. The ignored `real_macos_adapter_trains_in_unicode_paths` contract test executes the adapter-produced command with `splat-process` against the fixed public James40 dataset, checking the actual Metal backend, loader thread limit, source immutability and strict exported PLY validity. Its fixture placeholders for unrelated engines are explicitly outside the scope of that Brush-only test.

## Native preview receive boundary

The native desktop consumer keeps the renderer's little-endian float32 SH0–3 contract and 1 GiB file ceiling. Metadata polling reads only a bounded header and checks the declared byte layout. The IPC read opens the requested file once, checks the expected revision and size, allocates one response byte buffer, reads from the same handle, checks metadata again and fully validates the borrowed bytes in place. Non-finite values, truncation, duplicate Gaussian fields and unsupported SH/layouts are rejected before rendering. The core also exposes validation of an already-open file, avoiding validation against a newly opened replacement path.

Live frames must match the current UUID session, protocol, revision-derived filename and header Gaussian count before a request/ACK is written. Repeated ACK polls return no new frame; the frontend retains its installed live model rather than switching back to an older checkpoint. A failed byte decode or install does not advance the frontend ACK. Unknown or disabled live capabilities retain checkpoint viewing. A negotiated MetOrigin live protocol uses the same verified primary Brush executable; legacy Windows keeps its existing companion selection. Enabling a new engine's live capability remains contingent on the separate real-engine protocol and native-viewer verification.
